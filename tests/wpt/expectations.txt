# Known WPT failures for `gosub-wpt --expect`.
#
# Four record types, one per line:
#   FILE    <path>            a suite CI runs. Listed explicitly, so adding files to a wpt
#                             checkout cannot silently change what is covered.
#   FAIL    <path> :: <name>  a subtest expected to fail (control chars escaped \n \r \t).
#   HARNESS <path>            a suite whose harness does not finish cleanly (it timed out,
#                             or aborted) - separate from any individual subtest failing.
#   ERROR   <path>            a suite that cannot run at all here (a missing support file,
#                             or something the harness has no answer for).
#
# A listed test that starts passing is reported as an UNEXPECTED PASS, so this file has to
# be regenerated when behaviour improves:
#   gosub-wpt <wpt-root> --write-expectations $(paths...) > tests/wpt/expectations.txt
#
# Names are never trimmed on load: a subtest name may legitimately end in a space.
#
# Covered: dom/events and html/dom - the two directories the gosub_domjs bindings actually
# reach. The checkout also needs dom/nodes: three suites here pull support scripts out of it
# (Document-createEvent.js, DOMImplementation-createHTMLDocument.js, attributes.js) and turn
# into ERROR records without it. This file is pinned to the sparse set as much as to the
# commit in wpt-commit.txt - widen or narrow the checkout and the results move.
#
# Form controls are out of scope: that work lives on its own branch and needs engine modules
# (edit, form, focus) that are not on main yet.
#
# Not covered: dom/events/passive-by-default.html. It names three subtests identically (one
# per event target, all stringified "Object") and some of each trio pass while others fail.
# Expectations are keyed by name, so the trio collapses to one entry and the passing member
# is always reported UNEXPECTED PASS - the suite can never be green. Add it back if the
# records ever key on subtest index as well as name.
